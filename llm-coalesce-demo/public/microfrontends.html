llm-coalesce · microfrontends demo

Three microfrontends, one page, one call

Widget A, B, and C below are three genuinely separate ES module graphs — each one imports llm-coalesce from its own /vendor/mfe-*/llm-coalesce/ mount (see src/server.js), so each gets its own copy of every class and closure in the library, the same as three independently built and independently deployed bundles would. On the left, each one uses the library's default in-process registry — its own private Map, invisible to the other two. On the right, all three pass windowAdapter(), which reaches through the one object all three module graphs actually do share on a real page: window. Same key, same moment, two different outcomes — watch the server's own call counters.

This isn't three copies of one script tag with different labels — each of mfe-a.js, mfe-b.js, and mfe-c.js imports llm-coalesce from a distinct URL (/vendor/mfe-a/llm-coalesce/index.js, /vendor/mfe-b/…, /vendor/mfe-c/…), all three served from the identical node_modules/llm-coalesce/dist on disk. Browsers key ES module identity on the resolved URL, not file content, so those three imports — and everything each one transitively imports — are evaluated as three wholly separate module graphs. See TUTORIAL-microfrontends-live-demo.md for how this was verified in a real browser, not just argued from the source.
